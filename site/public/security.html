Security & Privacy Architecture

GrapheneOS Hardening

  • Built to run with Exploit Protection Compatibility Mode OFF (hardened_malloc, ARM MTE, memory/storage DCL disabled, native debugging blocked).
  • Zero WebViews, zero hybrid JS engines, and zero Google Play services / Firebase / analytics.
  • Zero broad storage permissions: strictly Storage Access Framework (SAF) and the system Photo Picker.
  • Offline-first: works cleanly with Network and Sensors revoked, inside secondary profiles and Private Space.

Cryptography & Local Storage

  • Local Records: Room over GrapheneOS's hardened system SQLite with application-layer Google Tink AES-256-GCM AEAD and canonical per-record Associated Authenticated Data (AAD).
  • Hardware Key Wrapping: Android Keystore Key Encryption Keys backed by StrongBox (Titan M2 / Secure Element) with hardware TEE fallback.
  • Encrypted Preferences: Tink-encrypted Jetpack DataStore (zero use of deprecated androidx.security:security-crypto).
  • E2EE Backups: Streaming AES-256-GCM-HKDF archives with pure-JVM Bouncy Castle Argon2id key derivation and authenticated headers, exported directly via SAF.

Trust Boundary

GitHub and Cloudflare are used solely as development, CI, and static hosting infrastructure. Shipped Android apps have zero runtime dependency on Google, Apple, or any third-party cloud. Optional self-hosted sync (planned in a later phase) is zero-knowledge ciphertext-only and deployable to each user's own Cloudflare account from this repository.

Full Threat Model and OWASP MASVS v2.1.0 Matrix are published in the repository.
